# Phase 5 Hosted Asset Runbook

Status date: 2026-08-25

Objective: publish and verify the browser widget asset served as `/voiceos.js` by the web app, while preserving evidence for the final acceptance criteria of Phase 5.

## Current local contract

- The dashboard snippet builder points to `https://<host>/voiceos.js`
- The widget browser bundle should be produced at `packages/widget/dist/voiceos.js`
- The widget build should synchronize the hosted asset to `apps/web/public/voiceos.js`
- The bundle size budget is `<= 60 KB` gzipped
- The canonical public session endpoint is:
  - `/v1/public/tenants/{tenant_id}/widget/sessions`

## Commands

Use these entry points from the repository root:

```text
npm --prefix G:\DEV\VOICE_OS run phase5:asset:ready
npm --prefix G:\DEV\VOICE_OS run phase5:widget:fallback
npm --prefix G:\DEV\VOICE_OS run phase5:acceptance
npm --prefix G:\DEV\VOICE_OS run phase5:evidence:package
npm --prefix G:\DEV\VOICE_OS run phase5:evidence:verify
make phase5-asset-ready
make phase5-widget-fallback
make phase5-acceptance
make phase5-evidence-package
make phase5-evidence-verify
```

## Evidence artifacts

- `reports/phase5-hosted-asset-readiness.json`
  - machine-readable readiness status for the hosted asset contract
  - current `next_gap` should be interpreted before claiming acceptance
- `reports/phase5-acceptance-summary.json`
  - local acceptance summary for static host example, React example, hosted snippet path, and the
    focused allowed-origin/public-key API test
- `reports/phase5-evidence-bundle.zip`
  - portable evidence bundle for handoff or external review
- `reports/phase5-evidence-bundle.manifest.json`
  - SHA-256 manifest of every bundled artifact plus the ZIP itself

## Acceptance interpretation

Current local evidence is sufficient to prove:

- snippet and dashboard wiring target `/voiceos.js`
- browser bundle generation logic exists
- sync target `apps/web/public/voiceos.js` exists
- size-budget enforcement exists
- host-page and React/Next examples align with the current contract
- the focused API test for allowed origin + public widget key passes locally
- `apps/web/public/voiceos.js` and `packages/widget/dist/voiceos.js` are materialized and byte-identical
- `packages/widget/dist/size.json` matches the generated bytes, SHA-256, and deterministic gzip size
- the current bundle is `3,686` bytes gzip, below the `61,440` byte budget

Current local evidence is not sufficient to prove:

- the hosted asset is externally reachable in staging or production
- Lighthouse and custom-domain TLS acceptance

## Managed Windows executor fallback

The canonical package build remains `npm run build --workspace=@voiceos/web`. When Node cannot
resolve `G:\` because of `EPERM`, use the repository-local native esbuild fallback:

1. Run `npm --prefix G:\DEV\VOICE_OS run phase5:widget:fallback`.
2. Confirm these files exist:
   - `packages/widget/dist/voiceos.js`
   - `apps/web/public/voiceos.js`
   - `packages/widget/dist/size.json`
3. Re-run:
   - `npm --prefix G:\DEV\VOICE_OS run phase5:asset:ready`
   - `npm --prefix G:\DEV\VOICE_OS run phase5:acceptance`
   - `npm --prefix G:\DEV\VOICE_OS run phase5:evidence:package`
   - `npm --prefix G:\DEV\VOICE_OS run phase5:evidence:verify`
4. Expect `phase5-hosted-asset-readiness.json` to report `passed: true`, `next_gap: null`,
   and `environment_blocker: null`.

## External delivery verification

After the bundle exists and `/voiceos.js` is deployed, run:

```text
npm --prefix G:\DEV\VOICE_OS run phase5:external:delivery -- --base-url https://<host>
python scripts/check_phase5_external_delivery.py --base-url https://<host> --expected-host <domain>
make phase5-external-delivery
```

Expected output artifact:

- `reports/phase5-external-delivery.json`

This verification should end with:

- `passed: true`
- HTTPS base URL
- external `200` for `/voiceos.js`
- non-empty response body
- JavaScript-compatible content type
